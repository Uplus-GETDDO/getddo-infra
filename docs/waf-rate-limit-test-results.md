# CloudFront IP별 요청 제한 테스트 결과

2026-10-25 운영 CloudFront에 WAF 요청 제한을 적용하고 실제 차단·자동 해제·로그 저장을 시험했다.
기준은 접속 IP별 최근 60초에 600회로 유지했다. 시험용 경로만 제거하고 요청 제한과 차단 로그는 계속 유지한다.

## 시험 목적과 구성

같은 IP의 과도한 API 요청을 앱에 도달하기 전에 차단하고,
정상 요청·다른 IP·제외 경로에는 기존 동작을 유지하는지 확인했다.

| 구성 | 설명 |
| --- | --- |
| 적용 위치 | 기존 CloudFront에 AWS WAF 연결 |
| 제한 기준 | 접속 IP별 최근 60초에 600회. 사용자 제공 X-Forwarded-For로 집계하지 않음 |
| 적용 범위 | 경로를 해석·정규화한 뒤 `/api/` 요청 집계. OPTIONS 제외 |
| 초과 응답 | 앱 전달 전 `429 / COMMON-006` JSON 반환 |
| 로그 | 차단 요청만 CloudWatch Logs에 저장, 7일 보관. 쿼리 문자열·인증 및 사용자 헤더 마스킹 |

WAF·로그 그룹은 `us-east-1`, 기존 서버·ALB·DB는 서울 리전에서 관리한다.
기존 백엔드의 요청 제한도 유지한다.

## 시험 방법

1. 적용 전 계정·티켓 조회의 정상 응답을 확인했다.
2. 짧은 로그 연결 확인 구간에서 정상 요청과 가짜 민감 값을 보내 로그 수신·마스킹을 확인했다.
3. ALB가 고유 본문을 직접 반환하는 임시 경로를 만들었다. 반복 요청이 앱·DB에 전달되지 않도록 했다.
4. 차단 모드와 차단 로그 전용 저장을 적용하고, 최대 12회/초·동시 2개·최대 1,800회 또는 150초 범위에서 요청했다. 첫 유효한 429 뒤 반복 요청을 중단했다.
5. 차단 중 헤더 변경·다른 IP·변형 경로·OPTIONS·이미지 조회를 확인했다.
6. 규칙을 바꾸지 않고 자동 해제를 확인한 뒤 정상 API를 다시 조회했다.
7. 실제 차단 로그·지표·보관 설정을 대조하고 임시 경로 삭제와 Terraform 전체 계획의 남은 변경을 확인했다.

자동 도구는 기준 응답·반복 요청·헤더 변경·복구 확인을 합해 857회 요청했다.
다른 IP와 제외 경로 검사는 별도 소수 요청으로 수행했다. 리다이렉트·자동 재시도는 사용하지 않았다.

## 최종 상태

- 기존 CloudFront에 WAF가 연결돼 있고 IP별 600회/60초 차단을 계속 유지한다.
- OPTIONS·이미지는 제외하고 기존 정상 API와 백엔드 제한을 유지한다.
- 차단 로그만 `aws-waf-logs-getddo-dev-api`에 저장하며 7일 후 만료한다. 초기 연결 확인 때 저장한 정상 로그도 같은 보관 기간을 따른다.
- 시험용 ALB 경로와 규칙은 제거했고 요청 발생 도구는 종료했다.

## 시험 범위

- **정확한 차단 순번:** AWS는 요청량을 추정한다. 850회에서 차단한 것은 이번 관측값이며 정확히 601번째 차단을 보장하지 않는다.
- **해제 시간:** 약 30초는 이번 관측값이며 고정 해제 시간이 아니다.
- **공유 IP:** 같은 네트워크의 사용자는 하나의 IP로 합산될 수 있다.
- **로그·지표 건수:** 로그 전달은 누락될 수 있어 요청·로그·지표 수가 정확히 같다고 요구하지 않는다.
- **검증 범위:** 정상 업무 읽기는 계정·티켓 조회 범위다. 브라우저 화면은 시험하지 않았고 EC2 직접 관리 경로는 CloudFront WAF 보호 범위 밖이다.

# CloudFront IP별 API 요청 제한 검증 결과

2026-10-25(KST) 기존 CloudFront에 연결한 WAF의 요청 제한·자동 해제·로그 저장을 실환경에서
HTTP 요청을 기준으로 확인했다. 기준은 처음부터 최근 60초에 600회/IP로 유지했다. 반복 요청에는 ALB가 고유 본문을
직접 반환하는 임시 경로를 사용해 앱과 DB에 부하가 전달되지 않도록 했다.

반복 요청은 전체 12회/초 이하·동시 2개·최대 1,800회 또는 150초로 제한했다.
유효한 첫 429를 관측한 즉시 반복 요청을 중단했으며 리다이렉트·자동 재시도는 사용하지 않았다.

| 케이스 | 방법·기대 | 실제 결과 |
| --- | --- | --- |
| 정상 읽기 | 계정·티켓 조회를 적용 전과 자동 해제 후 각각 3회씩 조회 | 두 API 모두 적용 전후 HTTP 200·성공 응답 유지 |
| 초기 로그·마스킹 | 짧은 Count/all 구간에서 정상 요청과 가짜 민감 값 전송 | ALLOW 로그 수신, 쿼리 문자열과 인증·사용자 헤더 7종 모두 REDACTED 확인 |
| 실제 차단 | Block·600/60초/IP에서 고정 응답 경로 반복 요청 | 반복 요청 850회·약 71초 구간에서 429 관측 후 중단 |
| 오류 응답 | 차단 응답의 본문과 헤더 대조 | 고정 COMMON-006 JSON·문구, JSON Content-Type, CORS `*`, Retry-After·credentials 허용 헤더 없음 |
| 헤더 변경 | 차단 중 같은 접속 IP에서 X-Forwarded-For만 변경 | 429 유지 |
| 다른 IP | 주 접속 IP가 앞뒤로 429인 동안 별도 IP의 기존 API 서버에서 소수 GET | 서로 다른 접속 IP를 초기 로그로 확인, 2회 GET 모두 200·고유 본문 |
| URI 변형 | 인코딩·중복 슬래시·상위 경로 표현이 있는 요청 | 3종 모두 429·COMMON-006, CORS `*` 유지 |
| 제외 경로·메서드 | 차단 중 OPTIONS와 기존 공개 SVG 조회 | OPTIONS 200·기존 CORS 응답, 이미지 200·image/svg+xml |
| 자동 해제 | 규칙 변경 없이 10초 간격으로 최대 5분 확인 | 반복 요청 중단 약 30초 뒤 200 복귀, 10초 간격으로 총 3회 연속 200·고유 본문 확인 |
| BLOCK 로그·보관 | 차단 요청의 경로·메서드·규칙·응답 코드와 원격 로그 설정 대조 | GET·ApiIpRateLimit·BLOCK·429 로그 수신, DROP + BLOCK KEEP, 보관 7일 확인 |
| 차단 지표 | 시험 시간대 us-east-1의 BlockedRequests 조회 | 60초 Sum 9인 데이터 포인트 1개 확인 |
| 정리·상시 유지 | 임시 규칙 삭제 후 배포·리스너·서버·전체 plan 재조회 | 임시 규칙 0, 기존 리스너 규칙·로그 전달 정책 유지, API 서버 2대 정상, 두 Terraform 구성의 남은 변경 0 |

자동 probe 도구는 기준 응답·반복 요청·헤더 변경·복구 확인을 합해 857회 요청 후 종료했다.
다른 IP와 제외 경로·메서드·URI 변형 확인은 별도 소수 요청으로 수행했다.

최종 확인 시각은 2026-10-25 11:15(KST)다. CloudFront는 Deployed 상태로 같은 Web ACL에
연결돼 있다. WAF는 `/api/` 범위에서 URI를 URL_DECODE 다음 NORMALIZE_PATH로 검사하고
OPTIONS를 제외하며 600회/60초/IP의 Block을 유지한다. 로그는 `us-east-1`의
`aws-waf-logs-getddo-dev-api`에 BLOCK 요청만 저장하고 7일 보관한다. 자동 해제와 임시 규칙
삭제 전후 WAF·로그 설정이 동일한 것을 확인했으며 WAF·로그 그룹·연결은 상시 유지한다.

850회와 약 30초는 이번 관측값이다. AWS의 추정 집계는 정확히 601번째부터 차단하거나 고정된
시간 뒤 해제하는 것을 보장하지 않는다. 공유 네트워크는 같은 IP로 합산될 수 있다. 로그 전달은
best effort이며 요청·로그·지표의 수가 정확히 같다고 요구하지 않는다. 정상 읽기 검증은 계정·티켓
조회 범위다. EC2 직접 관리 경로는 WAF 보호
범위 밖이고 기존 백엔드 요청 제한은 유지한다.

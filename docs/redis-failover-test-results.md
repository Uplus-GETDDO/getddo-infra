# 운영 Redis 장애 전환 테스트 결과

2026-10-25 운영 Redis를 두 AZ의 메인·복제본으로 구성한 뒤 실제 장애 전환을 1회 시험했다.
복제본의 메인 승격, 앱 재시작 없는 요청 제한 복구, 차단 이력의 DB 저장을 확인했다.
시험용 권한을 제거하고 이중화 구성은 유지했다.

## 시험 목적과 구성

메인 Redis를 사용할 수 없을 때 복제본이 역할을 이어받고,
API 서버 두 대가 기존 접속 주소로 다시 연결해 요청 제한과 이력 처리를 수행하는지 확인했다.

| 구성 | 설명 |
| --- | --- |
| 운영 Redis | Redis OSS 7.1.0, `cache.t4g.micro` 두 대, cluster mode disabled |
| 이중화 방식 | 다른 AZ에 복제본 한 대 배치. 비동기 복제·Multi-AZ·자동 장애 전환 사용 |
| 전환 전 역할 | 메인 `001`: `ap-northeast-2a` / 복제본 `002`: `ap-northeast-2c` |
| API 서버 | A는 `ap-northeast-2a`, C는 `ap-northeast-2c`. 앱 코드·연결 설정 변경 없음 |
| 연결·보호 | 기존 메인 DNS·6379·TLS·인증·사설 접근·저장 암호화·삭제 방지 유지 |

API 서버 두 대는 같은 Redis 메인을 사용한다. 복제본은 조회 분산용이 아니라 장애 대비용이다.
Redis 판정에 실패하면 기존 앱은 요청 제한을 건너뛰고 업무 검증을 계속한다.
비동기 복제이므로 전환 시 최근 카운터·차단 상태·DB 저장 전 이력이 일부 유실될 수 있다.

## 시험 방법

1. 두 노드의 AZ·역할·복제 연결과 API 서버 상태를 확인했다.
2. 합성 계정과 존재하지 않는 미션·이벤트로 요청했다. 업무 저장 전 거절되는 경로를 사용해 실제 응모·티켓 차감·보상·알림을 만들지 않았다.
3. A/C 요청이 같은 카운터에 합산되는지, 양쪽에서 429가 반환되는지, 만료 후 제한이 해제되는지 확인했다.
4. 관리형 장애 전환을 한 번 실행하고 역할 변경·앱 응답·Redis 재연결을 확인했다.
5. 전환 후 같은 제한 검사를 반복하고, 응모 평가용 연결과 차단 이력 저장용 연결도 실제 처리 결과로 확인했다.
6. 합성 차단 이력 한 개가 DB에 저장되고 Redis의 저장 대기 목록에서 빠지는지 대조했다.
7. 기존 노드의 복제본 복구, 임시 권한 삭제, Terraform 전체 계획의 남은 변경을 확인했다.

요청은 동시 한 개·최소 간격 1.1초로 총 44회 보냈고 서로 다른 요청 키 44개를 사용했다.
응답은 업무 거절 404가 30회, 제한 429가 14회였다. 앱·워커 재시작이나 별도 부하 시험은 수행하지 않았다.

복구 시간은 낮은 빈도의 최초 성공 표본이다. 정확한 장애 지속 시간이나 다음 장애의 복구 시간을 보장하지 않는다.
메인 승격 완료와 앱 기능 복구, 복제본 복구는 서로 다른 단계로 확인했다.

## 최종 상태

- 메인은 2c의 `002`, 복제본은 2a의 `001`에서 정상 동작한다. 기존 접속 주소·보안·엔진·사양을 유지했다.
- API 서버 두 대는 재시작 없이 공유 요청 제한·응모 평가를 다시 수행했다.
- 합성 차단 이력 한 개의 DB 저장과 저장 대기 해제를 확인했다. 원본 이력·글로벌 인덱스·DB 감사 표본을 수동 삭제하지 않았다.
- 임시 시험 권한은 제거했고, 이중화와 두 노드 모니터링은 계속 유지한다.

## 시험 범위

실제 역할 전환·양쪽 API의 제한과 만료 해제·응모 평가·합성 이력 저장은 위 케이스에서 확인했다.
다음 항목은 결과를 구분해서 해석해야 한다.

- **최근 데이터 유실:** 비동기 복제의 유실량이나 전환 직전 이력의 재처리를 재현하지 않았다. 전환 후 만든 이력의 한 번 저장이 무유실 보장은 아니다.
- **개별 워커 복구:** 실제 이력을 처리한 워커의 연결 복구는 확인했지만 A/C 중 어느 워커인지는 구분하지 않았다.
- **전체 요청의 무중단:** 시험 표본에 HTTP 5xx·timeout은 없었다. 일부 ALB 지표는 미발행이므로 전체 사용자 오류 0건으로 확대하지 않는다.
- **실패한 진단 명령:** 전환 중 API는 404를 반환했다. 그 뒤 별도 Redis 진단 연결에서 발생한 timeout을 앱의 HTTP timeout으로 기록하지 않았다.
- **전환 호출:** 최초 호출은 권한 거절됐고 후속 호출 한 번이 수락됐다. 실제 전환은 한 번이며 최초 거절 원인은 확정하지 못했다.
